# Google Drive 任务页面

## 独立直接上传

推荐流程为：下载 → MoviePilot 本地整理 → 监控整理完成目录上传到云端 drmedia → 云端二次分类归档到 media → 逐文件实时 STRM → 准备本地 NFO／图片 → 通知 Emby 扫描指定媒体库。目录任务填写“上传暂存文件夹 ID（drmedia）”与“云端归档文件夹 ID（media）”，二者必须位于同一共享盘且不同；两个相对路径字段分别是暂存与归档前缀。扫描允许提前预览最终分类路径，实际文件先按本地整理目录结构上传到 drmedia，云端校验通过后再移动到 media 的分类目录，保留同一文件 ID。STRM 播放前缀必须对应最终 media 根目录。单文件任务的云端归档相对路径需包含最终文件名，留空沿用上传路径。

上传和移动分别核验 ID、名称、大小、MD5、父目录、共享盘和任务归属。移动意图持久保存；响应丢失后显式重试先查询同一个云端 ID，不重复上传。归档重名、位置不符或文件缺失时停止后处理并保留本地源文件；不覆盖既有云端文件。归档完成后才生成 STRM、准备资料并扫库。旧任务及未填写云端归档 ID 的配置保留原直接上传行为；新目录请明确填写两个根目录。

“直接上传”页签通过 Google Drive API 把服务器本地文件直接上传到团队共享盘，独立于旧挂载复制开关。添加四个账号后先保存配置，再分别设置 Token；Token 接受 rclone 格式 JSON。自动续期需要对应 OAuth client_id、client_secret 和 refresh_token。凭据仅以 0600 权限写入服务器配置目录内的 `gdrive-upload`，父目录权限 0700，接口不回显。此版本支持 OAuth 用户账号，不包含服务账号 JSON 登录或浏览器 Google 授权流程。

总并发和每账号并发共同限制上传数量，例如总并发 4、四账号各 1，同时处理四个文件。每次上传可选择其中几个账号；任务选择当前负载最小的可用账号，同一文件固定一个账号续传。账号须具有同一团队共享盘目标文件夹的写入权限；可点击“检查账号与共享盘权限”只读核对。Google 的账号配额和限流仍然适用，配额错误记录为失败，可更新凭据或稍后重试。

新建上传填写服务器源文件路径、共享盘 ID 和目标文件夹 ID；网盘相对路径留空使用源文件名。已有同名云端文件会阻止新任务，避免覆盖；请指定不同文件名。任务保存 Google 可恢复会话及云端预分配 ID，重启、网络中断或最终响应丢失后使用同一文件恢复。完成依据为云端文件大小、MD5、目标归属校验成功，队列显示实际账号和云端文件 ID，并提供重试、取消入口。取消不删除云端数据或会话。

STRM 可选：填写本地输出根目录及媒体服务器能够播放的路径或地址前缀，生成普通 `.strm` 文本。Google 网页预览链接不等于媒体播放地址。源文件默认保留；选择删除时，只有上传及 STRM 成功才执行身份和内容复核后删除。

目录任务第一步可打开“通过 Google Drive API 直接上传”，选择账号、共享盘、暂存与最终归档目标；现有离线分类、命名规则、过滤、整理完成事件和定时补扫继续生效，目标分别交给独立上传队列。该模式不需要本地挂载点，STRM 根目录留空表示不生成 STRM。旧的“文件任务”新建和“挂载与 STRM 配置”继续用于挂载复制。

具有管理权限的用户和超级管理员可从“整理 → Google Drive”进入 `/gdrive`。

当前支持最近 100 条任务、状态筛选、已加载任务中的标题或路径搜索、手动刷新、新建任务、只读预检，以及任务详情和最近 200 条状态历史。页面可见且有未完成任务时每 5 秒刷新；离开页面后停止刷新。

## 新建任务

1. 填写服务器上的源文件完整路径。可选填写自定义归档路径，留空时使用后端配置生成的路径。
2. 核对完成后的源文件策略。默认继承当前配置；也可显式选择保留源文件或成功后删除源文件。页面会展示最终策略。
3. 运行只读预检，检查各项结果与最终归档、STRM 路径。修改任一路径后必须重新预检。
4. 预检通过且功能已启用后，点击“创建并启动”。此操作会立即启动后端归档任务。

预检不写入挂载目录，不证明真实挂载的写入能力。处理进度表示本地处理或复制，不能据此确认 Google Drive 云端同步完成。

如果未收到创建结果，任务可能已启动。请关闭窗口并刷新列表，核对是否已创建后再操作。当前窗口会阻止再次提交。

详情展示源文件、归档和 STRM 路径、状态、处理阶段、字节进度、重试次数、错误、源文件策略与历史；历史可单独刷新。

文件任务重试、取消和临时文件清理尚未提供页面入口，可使用后端对应接口。

## 目录任务与扫描历史

页面默认进入“归档任务”，另有“执行记录”“归档规则”“文件任务”页签。超级管理员可新建、编辑或删除目录任务；管理用户可读取配置及历史。新任务默认停用、递归扫描、保留源文件，保存不会启动扫描。编辑分为“基本信息与目录 → 归档规则与过滤 → 触发与源文件 → 流程与确认”。源目录、归档目录和挂载配置提供目录浏览窗口，可逐层进入、返回上级或选择当前目录，也可输入尚不存在的目标绝对路径。归档目录须在真实挂载点内，两者不得嵌套或包含符号链接。挂载与 STRM 配置入口可以修改总功能开关、挂载路径、默认归档路径及媒体服务器路径前缀；开启总功能前应核对已有定时任务。

过滤支持媒体扩展名白名单、忽略关键词、忽略后缀、最小大小（MiB）和静置时间（秒）。列表以逗号、分号或换行分隔，不区分大小写。静置时间按文件最后修改时间计算。扫描按所选规则命名，未选规则时保留相对目录结构；跳过符号链接、子挂载点及命中忽略关键词的子目录。单次遍历超过 10000 个目录项时，本批次不会提交文件任务。

“只读扫描预览”保存匹配结果和过滤原因，不写媒体及 STRM；总功能关闭时也可预览，但仍需真实挂载点。“扫描并归档”需要启用任务及总功能，并在确认后重新扫描、检查文件变化，再创建实际文件任务。同一文件版本已经存在文件任务时不会重新入队，包括失败和取消的任务；请到文件任务接口显式重试。

定时扫描按分钟间隔保存，每 30 秒检查到期任务，只有目录任务和总功能同时启用才运行。同一目录任务有活动批次时不能再次扫描、修改或删除；删除要求先停用，且会保留历史和文件记录。所有扫描时间按 UTC 展示。

历史显示最近 100 个批次，详情显示前 500 项并标注实际总数，包含遍历、匹配、跳过、入队、完成、失败/取消及执行中数量。服务中断扫描后保留已提交文件的关联和历史；尚未提交的文件不会自动补交。页面可见时每 5 秒刷新，离开目录页签或页面后停止。操作结果丢失时请先刷新历史及列表确认，避免重复操作。

## 归档规则与流程

“归档规则”中可新增可复用规则，分别编辑电影和剧集的目录、文件名模板及有序分类层级。点击变量可追加到当前模板；样例文件名会经过后端本地解析并显示完整相对目录树。扩展名自动保留。分类支持媒体类型、年份、分辨率、视频编码和制作组，按选择顺序从外向内排列。规则可供多个目录任务引用，删除前须移除所有任务引用。

规则预览解析本地文件名及父目录信息；实际目录批次还会复用整理事件、成功整理历史和 NFO，不请求 TMDB。TMDB ID 变量使用已有整理信息或文件名中的 ID 标记。缺少模板所需字段、跨季文件或路径过长时，该文件会记录具体原因，不入队。规则中的分类层级字段缺失时归入“未分类”。语法只支持明确的 `{{ 变量 }}`，不支持任意 Jinja2 表达式。先用电影和剧集样例确认规则，再保存目录并执行只读扫描查看真实文件结果。

批次保存目录配置和规则版本快照，修改规则仅影响之后的新批次。执行详情展示“扫描 → 过滤 → 预览路径 → 上传暂存 → 云端归档 → STRM → 本地资料 → 扫库 → 完成与源文件策略”；只读预览在路径计算后结束。单个文件的流程使用后端实际阶段，可继续打开文件详情查看状态历史和错误。旧挂载模式的复制进度仍不能表示云端同步进度。

## 整理完成接管与二级分类

“归档规则 → 新增二次分类规则”提供独立入口，也可编辑已有规则并启用自定义二次分类。规则可供多个目录任务引用；任务选择规则并使用沿用模式即生效，自定义／MoviePilot 模式可覆盖。规则中的分类随批次快照冻结，后续修改不影响已有批次。

分类列表点击目录名称可展开或收起，首条默认展开；完整路径摘要会自动换行，手机上的路径输入与排序／删除按钮分行。匹配语法说明默认收起，可按需查看。

支持电影／剧集分别配置、多层目录、顺序调整、YAML/TXT 导入及草稿转 YAML。导入仅替换草稿，仍须保存。普通条件全部满足，`?` / `？` 条件组至少一个满足；逗号普通值任选其一，`+` 值全部必需，`-` / `!` 排除，year / release_year 支持闭区间。空值兜底须放最后，缺失字段不满足排除条件。标题 keywords、已有标签 include_keywords 及系列字段均只读取本地信息。series_keywords / series_actors / series_directors 生成首个匹配词的“关键词系列”子目录；仅系列规则须命中系列，组合规则始终要求可选组命中。Symedia 官方部分系列示例与总则不一致，导入会提示本实现的明确语义，不宣称所有版本算法完全相同。

分类目录前缀可选自动添加电影／电视剧（旧策略默认），或直接相对归档根目录。导入已有“电影/…”“剧集/…”“动漫/…”路径时使用直接相对根目录，避免重复前缀。YAML 顶层仅支持 movie/tv 映射，拒绝重复键、未知字段、锚点／别名和非法路径，上限 256 KiB。归档规则预览可填写离线媒体 JSON；目录预览可填写标题、标签及演员／导演。标签和演职员不会在线补查。

目录编辑可选择“沿用媒体整理结果及所选归档规则”（默认）、“复用 MoviePilot 二级分类策略”或“自定义网盘分类策略”。自定义模式可单独覆盖所选规则，分别编辑电影、剧集分类名和条件，可上下移动优先级。未匹配可保留源文件并记录原因、进入指定分类或沿用原目录。

“离线分类预览”使用输入的样例文件名、标题、语种、国家、类型编号、年份、标签及演职员计算目标路径，不运行上传。MoviePilot 模式在预览时显示当前策略，每个实际批次冻结当时配置。分类按目录前缀选项与命名模板生成路径，忽略旧 categories 层级以避免重复。

“媒体整理完成后立即接管”默认选中，但新目录仍默认停用。启用目录及总功能后才接收范围内的本地整理完成文件，事件无需等待静置时间，其余过滤和扫描相同。重叠源目录不能同时启用。新事件可在扫描或上传期间持久化接收，与补扫使用同一指纹去重；中断事件可重放恢复。等待或活动批次期间不能修改、删除配置。

“本地 STRM 根目录”按最终归档结构生成文本 STRM，须与源目录和整个挂载目录隔离。留空沿用旧行为，在源文件旁生成。输出路径随文件任务保存，归档发生版本冲突时使用最终版本结构。媒体信息来自已有整理事件、本地历史及 NFO，不新增在线识别；NFO 中的类型仅复用数字编号、国家仅复用两位代码，缺失资料按未匹配策略处理。

## 离线验证

`src/pages/__tests__/gdrive.spec.ts` 使用 MSW 拦截 HTTP 请求，不接触真实后端、挂载目录或外部服务。运行项目的 `yarn test:run src/pages/__tests__/gdrive.spec.ts`、`yarn typecheck`、`yarn lint`、`yarn test:coverage` 和 `yarn build` 完成验证。

项目推荐 Node 24。若使用 Node 26，jsdom 测试可能受 Node 实验性 Web Storage 影响，可在测试命令前设置 `NODE_OPTIONS=--no-experimental-webstorage`。

开发服务器可用 `yarn dev --port 5179` 启动，应用入口为 `/#/gdrive`，需要登录并拥有管理权限。开发服务器通过现有 `/api/v1` 代理连接本机 3001 端口的真实后端；页面展示真实接口返回的数据。
